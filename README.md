# MyFindNarratives

주식시장을 움직이는 **내러티브(시장이 믿고 있는 이야기)** 를 찾아내고 기록·추적하는 저장소.

**운영 방식: 요청 기반.** Claude 대화창에서 "내러티브 업데이트해줘"처럼 요청하면, Claude가 그 시점의 시장을 리서치해 이 저장소에 기록하고 GitHub에 푸시한다. 자동 스케줄은 없다.

가격은 결국 숫자로 남지만, 그 숫자를 만든 "왜"는 금방 잊힌다.
이 저장소는 그 "왜"가 언제 태어나서, 어떻게 확산되고, 언제 깨졌는지를 남기는 일지다.

## 구조

```
MyFindNarratives/
├── README.md              # 이 파일 — 목적과 사용법
├── CLAUDE.md              # 요청 시 Claude가 따르는 작업 절차
├── INDEX.md               # 현재 추적 중인 내러티브 한눈에 보기 (대시보드)
├── templates/
│   ├── narrative.md       # 내러티브 1개 = 파일 1개 (살아있는 문서)
│   └── snapshot.md        # 스냅샷 (요청 시점 시장 전체의 단면)
├── narratives/            # 내러티브별 파일. 계속 업데이트되며 타임라인이 쌓임
│   └── <id>.md
└── snapshots/
    └── YYYY/YYYY-MM-DD.md # 요청 1회 = 스냅샷 1개. 한번 쓰면 수정하지 않음
```

**두 종류의 기록**

| 종류 | 위치 | 성격 |
|---|---|---|
| 내러티브 파일 | `narratives/<id>.md` | 하나의 이야기의 **생애**를 추적. 계속 덧붙여 쓴다 |
| 스냅샷 | `snapshots/YYYY/YYYY-MM-DD.md` | 특정 시점의 **시장 단면**. 작성 후 수정 금지 (사후 확증편향 방지) |

## 내러티브 생애주기 (상태)

`태동` → `확산` → `주류` → `과열` → `쇠퇴` → `소멸`
(어느 단계에서든 `반전` 가능 — 반대 내러티브로 뒤집힌 경우)

- **태동**: 일부 리포트/커뮤니티에서만 언급. 가격 반영 미미
- **확산**: 주요 언론 헤드라인 등장, 관련 자산 움직이기 시작
- **주류**: 컨센서스. "다들 아는 이야기". 가격 상당 부분 반영
- **과열**: 반대 의견이 조롱받음, 밸류에이션·포지션 극단
- **쇠퇴**: 검증 지표가 이야기를 배신하기 시작
- **소멸**: 더 이상 가격을 설명하지 못함

## 강도 (1~5)

| 점수 | 의미 |
|---|---|
| 1 | 언급만 있음 |
| 2 | 특정 섹터/종목 일부에 영향 |
| 3 | 섹터 단위 흐름을 설명 |
| 4 | 지수 방향에 영향 |
| 5 | 시장 전체를 지배 (거의 모든 자산이 이 이야기로 움직임) |

## 사용법 (대화창에서 이렇게 요청)

| 요청 예시 | Claude가 하는 일 |
|---|---|
| "내러티브 업데이트해줘" / "요즘 시장 내러티브 찾아서 기록해줘" | 마지막 스냅샷 이후 ~ 오늘까지 리서치 → 전체 업데이트 + 새 스냅샷 → 커밋·푸시 |
| "FOMC 결과 반영해줘" / "AI 쪽만 업데이트해줘" | 해당 내러티브만 타임라인 갱신 (스냅샷 없이) → 커밋·푸시 |
| "새 내러티브 추가: ○○" | 리서치 후 `narratives/`에 신규 파일 → 커밋·푸시 |
| "지금 기록된 내러티브 요약해줘" | 리서치 없이 저장소 내용만 읽어서 답변 (커밋 없음) |
| "○○ 내러티브 종료 처리해줘" | 상태를 소멸/반전으로 바꾸고 회고 작성 → INDEX의 종료 표로 이동 |

세부 절차는 `CLAUDE.md` 참고.

## 원칙

- **사실과 해석을 분리**한다. 수치에는 날짜와 출처를 붙인다.
- **단일 출처 수치는 `(단일출처)`** 로 표시한다. 출처 간 수치가 다르면 둘 다 적는다.
- 내러티브마다 **무효화 조건**을 반드시 적는다. "무엇이 보이면 이 이야기는 끝인가?"
- 스냅샷은 사후 수정하지 않는다. 틀린 판단도 기록의 일부다.
- 이 저장소는 투자 조언이 아니라 관찰 일지다.
